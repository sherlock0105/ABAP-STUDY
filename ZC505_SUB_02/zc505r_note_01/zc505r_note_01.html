* 컨셉을 지역변수로 잡기
* 변수 선언하는 형식
* Data <변수명> Type <Built in> Length <길이> or <Dictionary>.
* CHAR 20 자리를 선언해보자

DATA lv_name TYPE c LENGTH 20. "원시적인 표현
DATA lv_name2(20) TYPE c. "Length 대체 표현
*TYPE 이 생략이 되면 기본 CHAR 타입이 된다.
DATA lv_name3(20). "CHAR type 길이 20 의 표현
DATA lv_name4. "CHAR type 길이 1 자리 (길이생략시 CHAR의 기본길이)

*DATA 가 너무 중복으로 나온다.

DATA : lv_name5(20) VALUE 'CODE1',
       lv_name6(20) VALUE 'CLASS 5',
       lv_name7(30) VALUE '페퍼로니피자 먹고 싶다',
       lv_numc1     TYPE n,
       lv_numc2(5)  TYPE n,
       lv_int1      TYPE i VALUE 1234,
       lv_pack(16)  TYPE p DECIMALS 2 VALUE '12343.23'. "소수점을 입력하고 싶을때는 '' 로 묶어주고 DECIMALS 2 작성

lv_numc2 = -1.
lv_int1 = - lv_int1. "-1 을 곱하는 약식 표현, 음수는 무조건 뒤에 붙는다.

*LV_INT1 *= -1. 이것도 가능하다

WRITE :/, lv_numc1, /,lv_numc2, lv_int1, lv_pack.
*WRITE : lv_name5,/, lv_name6,/, lv_name7.

* ACTIVE 된다? -> 에러가 없다는 것

* Data <변수명> LIKE <Local Type>/

DATA : lv_name8 LIKE lv_name5. "클론 똑같이 만들어주는 것이 LIKE 다
*값을 가져오는게 아니라 타입과 길이만 가져온다.

*ZC505DE_PA_NAME
*Global Data Type 중 Dictionary 를 이용해보자 : 단, Domain은 사용 못함
* 왜냐... 이미 Data Element 가 Domain 과 연결이 되어있을 수 있는 객체이므로

*Like 는 여기 소스 안에서만 돌고 type 은 dictionary 로 가서 확인한다.

DATA : lv_pa_name TYPE zc505de_pa_name,
       lv_matnr   TYPE matnr,
       lv_werks   TYPE werks_d, "data elemental 을 바로 입력
       lv_plant   TYPE zc531t0018-werks. "data elemental 이름이 기억이 안날때 ,
*이걸 가장 많이 사용한다. 왜? 데이터 엘리멘트를 알기가 힘들어서 테이블에 있는 필드를 입력한다.

lv_pa_name = '안녕'.

WRITE : /,lv_pa_name.

DATA : lv_count(3)  TYPE n,
       lv_descr(50),
       lv_qty       TYPE p DECIMALS 3,
       lv_material  TYPE matnr,
       lv_plant2    TYPE werks_d,
       lv_lgort     TYPE t001l-lgort.

*lv 는 로컬 데이터 타입  , 프로그램 안에서만 존재함 , gs 는 글로벌 전체에서 사용가능

DATA : lv_count2    LIKE lv_count,
       lv_descr2    LIKE lv_descr,
       lv_qty2      LIKE lv_qty,
       lv_material2 LIKE lv_material,
       lv_werks2    LIKE lv_plant2,
       lv_lgort2    LIKE lv_lgort.

WRITE : /, lv_plant2, lv_descr2, lv_qty2, lv_material2, lv_werks2, lv_lgort2.
